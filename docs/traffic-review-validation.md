# 流量审查验证记录（2026-10-18）

## 2026-10-19：代理流量与自动账单比对

主页改为代理出站/入站载荷及 ChatGPT 预设候选，网卡、内核与原趋势移至诊断折叠区。代理总出站为远端上传加发回客户端下载；入站合计由同一批转发载荷镜像推导，明确不作为两次独立实测相加。

新增三组业务小时汇总、分钟边界汇总和独立代理采集心跳。只有心跳覆盖完整、业务历史齐全且已有真实 SKU 行的洛杉矶账单日参与比对；缺测和缺账单不补成零。至少 7 个可比日后比较变化，检查未知域名、其他流量混杂、常量数据与多项目边界；新账单或更正导入后自动重算。短日期查询显式回看此前 35 日，保持主统计范围不变。

回归覆盖域名后缀防误匹配、UDP/未知域名隔离、上下行镜像口径、覆盖心跳中断与空闲零值、7–10 日模拟相关/混杂/无候选仍有收费、账单更正及精确净额、多项目/币种隔离、历史截止与夏令时、幂等迁移、长期留存、服务真实代理收发到覆盖基线，以及每日同步定时器。Carrier Peering 仅明确 Americas 的目标描述或兼容 SKU 标识参与该分项，其他地区保留为其他项目。

本轮没有改动生产 VPS 或用真实账单证明 ChatGPT 导致该费用；ChatGPT 仍是用户指定的候选假设，程序不分摊单站费用、不自动改路由，也不将 `flowBillingConfirmed` 设为 true。

## 日期范围与流量口径修复

本轮重新通过 SSH 只读检查用户 VPS。采集器和面板均运行，`nf_conntrack_acct=1`，事件健康记录无解析错误或事件丢失。一次 66 条连接的快照中，7 条为本机环回连接，其余均能按现有规则判断收发方向；旧版本将这些不经过监控网卡的环回连接误报为 `direction_gap`。旧版本也对正常 NEW 事件暂缺字节计数产生误报，已分别修正。真实目标连接后续仍缺计数时继续报告，不隐藏采集缺口。

现场数据库没有代理记录或代理水位；原页面用 SQL 零值填充造成“代理上传/下载为 0”的误导。现以观测计数区分“无记录”和“已观测的真实零值”，新增真实 HTTP 代理上传、下载经核心跟踪器、服务转换到本地数据库的集成验证。

已在 VPS 临时目录运行新采集器 15 秒：使用独立数据库，并实际建立 10 条本机环回连接，采得 9 条网卡样本；`direction_gap` 和 `byte_counter_gap` 均为 0，公网方向仍有正常记录。另对生产审查库的快照副本执行迁移，小时汇总与原分钟数据总量一致，SQLite 完整性检查为 `ok`。生产面板和采集服务保持运行，未替换生产二进制。

新增起止日期（含结束日）和最长 3 个日历年的查询；小时总量独立保留 3 年，明细仍保持 7 天和容量上限。迁移仅回填尚存的旧数据。回归覆盖日期/夏令时/闰年、六项页面请求共用区间、无效区间暂停与旧响应丢弃、旧库幂等迁移、明细清理后总量保留、小时/分钟边界不重复计数、完整三年趋势不被截断、正负差额及缺测不冒充零值。

网卡 TX 与内核出站差额不代表 Google 额外收费。费用仍仅来自已导入的项目/日期/SKU 账单，不能确认单条连接费用。本轮未改动生产服务、数据库或代理配置；此前已经发生的误报保留为历史记录。

## 范围与结论

已实现原生 S-UI 菜单、Cookie 鉴权只读 API、独立本地 SQLite、接口/连接/代理载荷三层采集、候选规则版本、人工账单导入及可选 BigQuery Standard export 同步。未调用 Google 监控或 Cloud Billing API；可选同步调用 BigQuery API。**可以从启用时起积累流量证据并记录 SKU 费用，不能仅靠 VPS 证明哪条连接实际被 Google 收费。**

## 此前独立复核与修复

此前一轮的 VPS / 浏览器验证来自交接记录，该轮没有重新连接生产 VPS；执行了 Linux test profile 全套 Go 测试、go vet、受影响包竞态检查，以及前端测试、lint、类型检查、生产构建和 Linux 二进制构建。该轮新增回归覆盖：

- 太平洋自然日与夏令时边界，避免滚动窗口用部分日覆盖完整日汇总。
- BigQuery 未完成查询等待、结果分页和完整行数校验，分页失败不导入部分日数据。
- 查询预算跨 SQLite 实例串行预留；超时、解析失败和崩溃不会释放可能已产生的查询费用。
- 混合币种仅汇总用量，金额返回不可用；原币种仍保存在原始账单。
- 汇总绕过明细列表 500 行上限；200 GiB 参考采用已导入的太平洋自然月项目用量，不标作单台 VM 的实际剩余额度。
- Google 带负用量的更正记录可以参与日汇总；缺少任一对比窗口的账单时拒绝宣称中转节省费用。
- 中转预览移除无效 `status` 路由字段，并由当前 sing-box 规则解析器实际验证。
- 采集器使用 systemd 就绪通知；面板的启动依赖等待独立库和 WAL 打开，减少 root 面板先创建监控用户无权访问的 WAL 的启动竞争。

Standard 免费额度不覆盖所有 SKU；Carrier Peering 名称也可能来自 CDN Interconnect。仅按网站、ASN、出口为 direct 或“没有手工中转”进行收费分类不充分。规则命中始终是候选；CSV 保留项目/账单日/SKU 范围和精确十进制文本，不按域名分摊费用。参见[部署及证据边界](traffic-review.md)。

## 修复闭环

真实验证发现并修复：新 API 未登录请求错误跳到面板路径之外；conntrack 1.4.6 的事件模式不接受 `-f`；采集器同一 Unix 秒快速重启报错；`cmd.Wait` 先于 stderr 读完导致健康状态误报降级。均有对应回归检查，随后重新构建并在 VPS 复测。概要接口也返回真实采样间隔。

前端源码从固定子模块版本并入本仓库，避免菜单修改依赖另一个未发布仓库；大部分新增行数来自原有前端的原样纳入。
